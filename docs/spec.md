# NORN（ノルン）システム開発仕様書

- **ファイル:** `docs/spec.md`
- **バージョン:** 1.3
- **対象:** OS非依存・Web-first型のパーソナルAI秘書
- **ステータス:** 初期開発仕様
- **更新日:** 2026-11-01

---

## 1. プロジェクト概要

### 1.1 目的

NORNは、ユーザーの目標・予定・タスク・行動履歴を継続的に把握し、日々の計画立案、進捗管理、タスク調整を支援するパーソナルAI秘書である。

単なるチャットボットではなく、将来的には以下のサイクルを継続的に実行するエージェントとして設計する。

1. **Observe:** 状況を収集する
2. **Think:** 状況と目標を分析する
3. **Plan:** 計画を立案する
4. **Act:** 許可された操作を実行する
5. **Evaluate:** 結果を評価し、次の計画に反映する

初期開発では、まずローカル環境で動作するWebアプリケーションとして基盤を構築する。自律エージェントや音声機能を最初から実装せず、段階的に機能を追加する。

### 1.2 管理対象

- **学習:** プログラミング、AI、技術習得
- **創作:** 作曲、ギター、動画制作
- **生活:** 仕事、睡眠、運動、家事
- **予定・目標:** 日々のタスク、中長期目標、進捗

### 1.3 基本方針

- 特定OSに依存しないコア機能を構築する。
- 初期版はローカルPC上で動作するWebアプリケーションとする。
- 音声入力を主な会話手段とし、テキスト入力は音声を使えない場合の代替手段として提供する。
- UI、API、ビジネスロジック、記憶、LLM、音声入出力を分離する。
- LLM・STT・TTS・外部サービスを将来交換できる構造にする。
- 重要な操作には権限管理と監査ログを設ける。
- 個人データ、APIキー、音声モデルをソースコードから分離する。
- 自律性と安全性を両立させ、実行結果を追跡可能にする。
- 初期段階ではクラウドへの公開を必須としない。ローカル利用を基本とする。
- 将来のデスクトップアプリやモバイルクライアント追加を妨げないAPI設計とする。

## 2. 技術方針

技術選択は交換可能性を考慮し、初期実装では以下を採用する。

| 項目 | 初期方針 |
|---|---|
| 対応OS | OS非依存を目標とする（開発・初期動作確認はWindows） |
| フロントエンド | React + TypeScript + Vite |
| バックエンド | Python + FastAPI |
| Python | 3.12系を初期開発環境として採用 |
| API | REST APIを基本とし、必要に応じて拡張 |
| データベース | SQLite |
| LLM | クラウドAPIを初期候補とし、プロバイダー交換可能なアダプター経由で接続 |
| 記憶検索 | 初期はSQLite。必要に応じて全文検索・ベクトル検索を追加 |
| 定期実行 | APScheduler等を候補とし、導入時に要件を確認 |
| カレンダー | 初期はNORN内で管理。外部カレンダー連携は後続フェーズ |
| 音声認識 | MVPで導入。STTアダプター経由で接続し、エンジンはPhase 1で選定 |
| 音声合成 | Style-Bert-VITS2を初期採用。TTSアダプター経由で接続 |
| デプロイ | 初期はローカル起動。クラウド公開は後続検討 |

### 2.1 アーキテクチャ方針

- フロントエンドはバックエンドAPIを通じてデータへアクセスする。DBへ直接接続しない。
- バックエンドはUIに依存しないビジネスロジックを保持する。
- LLM、STT、TTS、DB、カレンダー連携はインターフェースまたはアダプターで抽象化する。
- APIの入出力スキーマを定義し、クライアントとサーバーの依存を疎結合にする。
- 初期のローカル構成でも、将来別端末からAPIを利用できる構成を意識する。
- ローカルAPIは原則 `127.0.0.1` にバインドする。LAN・インターネット公開は認証・通信保護等を設計してから行う。

### 2.2 Python環境

NORN本体専用の仮想環境を使用する。Style-Bert-VITS2はPyTorch等の依存関係とモデル実行負荷を分離するため、NORN本体とは別の仮想環境・プロセスで実行する。依存パッケージはそれぞれのプロジェクト単位で管理し、既存環境を変更・共有しない。Style-Bert-VITS2側のPythonは、採用バージョンが対応する範囲（現行リポジトリではPython 3.10以上3.14未満）から選ぶ。

### 2.3 LLM・音声に関する方針

- LLMは特定ベンダーに固定しない。
- 音声認識はMVPの主要な入力経路とするが、STTエンジンは独立したアダプターとして分離し、利用できない場合もテキスト入力を可能にする。
- 初期TTSエンジンとしてStyle-Bert-VITS2を採用し、NORNからはTTSアダプター経由で利用する。NORN本体はエンジン固有のライブラリや起動方法に直接依存しない。
- Style-Bert-VITS2の推論には、互換性を確認したバージョン、設定ファイル、対応する音声モデルおよび必要なBERT関連データを使用する。NORN用の音声モデルはStyle-Bert-VITS2の学習・推論仕様に合わせて管理する。
- 音声合成はStyle-Bert-VITS2の推論ライブラリを独立したワーカープロセスから呼び出す方針とする。エディターUIや未安定の開発用APIサーバーをNORNの実行依存にしない。ワーカーとの通信方式とモデル引数は実装時に採用バージョンを確認して確定する。
- 話者・スタイル等の指定は、選択したモデルとStyle-Bert-VITS2のバージョンがサポートする範囲でアダプターから設定する。
- STTエンジンはPhase 1開始時に、認識精度、応答速度、ローカル実行可否、利用条件を確認して選定する。具体的なエンジンはアダプターの背後に置き、交換可能にする。
- Style-Bert-VITS2のモデル重み、設定ファイル、BERT関連データ、参照音声、学習データはGit管理対象外とする。モデルの利用・再配布条件を個別に確認する。

クラウドLLMを利用する場合、会話や予定などの個人情報が外部APIへ送信される可能性がある。送信対象を最小化し、APIキーは環境変数または安全な資格情報保管機能で管理する。

## 3. 想定利用シナリオ

### 3.1 朝の予定確認

ユーザーが「今日の予定は？」と音声で尋ねると、NORNは発話をテキスト化し、当日の予定、未完了タスク、目標の優先度を参照して実行可能な計画を提示する。音声を利用できない場合はテキストでも同じ操作を行える。

### 3.2 タスクの追加

「明日、Pythonを1時間勉強したい」と伝えると、NORNはタスク候補を作成し、所要時間・期限・優先度を記録する。日時が曖昧な場合は勝手に確定せず、必要な確認を行う。

### 3.3 予定の再調整

「今日は疲れたので作曲を休みたい」と伝えた場合、NORNはタスクを未完了として記録し、期限や他の予定を考慮して移動案を作成する。許可されたルールの範囲内なら自動調整し、重要な予定に影響する場合は確認する。

### 3.4 プロジェクト進捗の確認

「今作っている曲の進捗は？」という質問に対して、該当プロジェクトの状態、完了タスク、次の作業を記憶から取得して回答する。

### 3.5 日次振り返り

一日の終わりに予定と実績を比較し、達成・未達・予定変更の理由を記録して翌日の計画に反映する。

## 4. 機能要件

優先度は **P0（MVP必須）/ P1（初期拡張）/ P2（将来機能）** とする。各機能はフェーズに分けて実装し、P0であってもPhase 0から一括実装することを意味しない。

### 4.1 会話・AIコア

- **FR-001 [P0]** 音声入力を主な手段としてLLMと会話できる。音声が利用できない場合のテキスト入力も提供する。
- **FR-002 [P0]** LLMプロバイダーをアダプター経由で接続し、特定ベンダーに依存しない。
- **FR-003 [P0]** 会話履歴を保存し、過去の会話を参照できる。
- **FR-004 [P0]** NORNが利用できるツールと権限を明示的に管理する。
- **FR-005 [P0]** LLMの応答とツール実行を区別し、実行結果を検証してからユーザーに報告する。
- **FR-006 [P1]** 会話から目標・タスク・プロジェクト候補を抽出し、必要に応じて確認して登録する。
- **FR-007 [P1]** 定期的な状況分析と計画更新を行う。

### 4.2 音声入出力

- **FR-010 [P0]** STTアダプターを介して音声をテキスト化できる。録音はユーザー操作で開始・終了し、認識結果を送信前に確認・修正できる。
- **FR-011 [P1]** Style-Bert-VITS2を使うTTSアダプターを介して応答音声を生成・再生できる。
- **FR-012 [P0]** 音声入力とテキスト入力で同じ会話処理経路を利用する。
- **FR-013 [P1]** 音声生成に失敗した場合、テキスト表示にフォールバックする。
- **FR-014 [P2]** 音声の再生停止、音量調整、出力先設定を行える。
- **FR-015 [P2]** ウェイクワードによる呼び出しに対応する。
- **FR-016 [P2]** 音声による割り込み、連続対話、発話中断に対応する。

音声エンジン固有のAPI・起動方法・モデル形式はアダプター内に閉じ込める。モデル重み・参照音声・参照テキストはユーザーがローカルに設定し、Gitリポジトリへ含めない。音声の本人同意と、モデル・音声データを第三者へ再配布する許可は別に扱う。

音声認識はユーザーが録音操作を行った場合にのみ実行し、ウェイクワードや常時マイク待機は初期版では行わない。初期設定では生音声を保存せず、会話履歴には認識テキストを保存する。外部サービスへ音声を送信する構成では、送信先と送信の有無を設定画面で明示する。

初期TTSのStyle-Bert-VITS2は独立したワーカープロセスで推論する。モデル未設定、ワーカー停止、推論失敗時はエラーを記録してテキスト応答を継続する。話者・スタイル・速度等の設定項目は、採用モデルと固定したエンジンバージョンがサポートする範囲に限定する。

### 4.3 タスク管理

- **FR-020 [P0]** タスクを追加、取得、編集、完了、取り消しできる。
- **FR-021 [P0]** タスクにタイトル、説明、期限、所要時間、優先度、状態を持たせる。
- **FR-022 [P0]** 未完了タスクと期限超過タスクを一覧表示できる。
- **FR-023 [P1]** 大きな目標を複数の小タスクに分解できる。
- **FR-024 [P1]** タスクの見積時間と実績時間を記録できる。
- **FR-025 [P1]** 繰り返しタスクを設定できる。

### 4.4 目標・プロジェクト管理

- **FR-030 [P0]** 長期目標を登録・編集・終了できる。
- **FR-031 [P0]** プロジェクトを目標に関連付けられる。
- **FR-032 [P0]** プロジェクトの状態、進捗、次のアクションを記録できる。
- **FR-033 [P1]** 学習、作曲、動画制作などのカテゴリで分類できる。
- **FR-034 [P1]** 目標の進捗を定期的に評価できる。

### 4.5 スケジュール・計画

- **FR-040 [P0]** NORN内の予定を登録・取得・編集できる。
- **FR-041 [P0]** 予定とタスクを区別する。予定は時間が確定したイベント、タスクは実行すべき作業とする。
- **FR-042 [P0]** 所要時間、期限、優先度、既存予定を考慮して計画案を作成する。
- **FR-043 [P0]** 重複予定や実行不可能な計画を検出する。
- **FR-044 [P1]** 計画と実績を比較し、再計画できる。
- **FR-045 [P1]** Google Calendar等の外部カレンダーと同期できる。
- **FR-046 [P1]** 勤務時間、睡眠時間、休憩時間などユーザー設定を計画に反映する。

### 4.6 記憶

- **FR-050 [P0]** 会話履歴、プロフィール、目標、プロジェクト、タスク、予定を区別して保存する。
- **FR-051 [P0]** LLMへ渡す情報は質問やタスクに関連するものに限定する。
- **FR-052 [P0]** 記憶の出典、作成日時、更新日時を可能な範囲で保持する。
- **FR-053 [P1]** 過去の行動・実績を検索し、計画に利用できる。
- **FR-054 [P1]** ユーザーが記憶を確認・修正・削除できる。
- **FR-055 [P2]** ベクトル検索による意味的な記憶検索に対応する。

### 4.7 自律エージェント

- **FR-060 [P0]** Observe / Think / Plan / Act / Evaluateの処理を分離する。
- **FR-061 [P0]** エージェントが実行できる操作を登録済みツールに限定する。
- **FR-062 [P0]** ツール実行前後の入力・結果・実行時刻をログに残す。
- **FR-063 [P0]** 同じ操作の重複実行を防止する。
- **FR-064 [P0]** エラー時に無限リトライせず、安全に停止する。
- **FR-065 [P1]** 定期的に未完了タスク、期限、目標進捗を点検する。
- **FR-066 [P1]** 実績を評価して計画を更新する。
- **FR-067 [P1]** AUTO / APPROVAL / DENYの権限をツール単位で設定できる。

## 5. 自律性・権限モデル

自律型であっても、すべての操作を無制限に実行させない。各ツールに権限レベルを設定する。

| 権限 | 動作 | 例 |
|---|---|---|
| AUTO | 条件内で自動実行 | タスク追加、進捗記録、日次レポート |
| APPROVAL | 実行前に確認 | 確定済み予定の変更、外部カレンダーへの変更 |
| DENY | 実行禁止 | 金銭取引、無断送信、権限変更、秘密情報の外部送信 |

初期設定：

- タスク追加・完了記録：AUTO
- 優先順位の提案：AUTO
- NORN内の仮予定作成：AUTO
- 確定済み予定の変更：APPROVAL
- ファイル読み取り：許可されたフォルダのみ
- ファイル削除・上書き：APPROVAL
- メール・SNS等の送信：APPROVAL
- 金融取引・購入：DENY
- 自身の権限変更：DENY

確認を得ていない操作を実行済みとして報告してはならない。AIが自分自身の権限を拡張できない設計にする。

## 6. 非機能要件

### 6.1 安定性

- LLM・音声認識・音声合成・定期処理は、必要に応じて非同期またはバックグラウンドで実行し、UI操作を阻害しない。
- APIタイムアウト、ネットワーク切断、モデル読み込み失敗を処理する。
- 音声機能が停止しても、テキスト操作とタスク管理は継続できる。
- DB更新にはトランザクションを利用する。
- バックエンド停止時にフロントエンドが適切なエラー状態を表示する。

### 6.2 セキュリティ・プライバシー

- APIキー、パスワード、音声データ、個人DBをGitへコミットしない。
- LLMに送信する個人情報を最小化する。
- ローカルAPIは原則 `127.0.0.1` にバインドする。
- 外部アクセスを許可する場合は認証・通信保護を必須とする。
- ファイル操作は許可ディレクトリ内に限定する。
- ログにAPIキーや音声の生データを出力しない。
- DBのバックアップ・復元手段を用意する。
- CORS等のAPIアクセス制御を必要最小限に設定する。

### 6.3 保守性

- LLM、STT、TTS、DB、カレンダー連携をインターフェースで抽象化する。
- UIとビジネスロジックを分離する。
- 設定値をコードへハードコードしない。
- 型ヒント、ログ、単体テストを整備する。
- APIスキーマとデータモデルの変更を追跡可能にする。

### 6.4 パフォーマンス・互換性

- 定期処理は必要なタイミングでのみLLMを呼び出す。
- Style-Bert-VITS2の音声モデルは必要に応じてロード・アンロードできる設計にする。
- GPUメモリ不足や音声ワーカー障害時にテキストのみの動作へ切り替えられること。CPU推論は採用モデル・実行環境で動作確認できた場合に限り選択可能とする。
- 初期開発環境（RTX 2070 SUPER 8GB、RAM 32GB、Core i7-10700）での動作を目指す。
- 特定OS固有の機能をコアロジックへ直接組み込まない。
- 対応ブラウザやOSの詳細なサポート範囲は、必要になった段階で定義する。

## 7. システム構成・モジュール設計

### 7.1 初期リポジトリ構成

```text
norn/
├── frontend/                 # React + TypeScript + Vite
│   ├── public/
│   ├── src/
│   │   ├── components/
│   │   ├── features/
│   │   ├── lib/               # APIクライアント等
│   │   └── App.tsx
│   └── package.json
├── backend/                  # Python + FastAPI
│   ├── app/
│   │   ├── api/
│   │   ├── core/
│   │   ├── database/
│   │   ├── schemas/
│   │   └── main.py
│   ├── tests/
│   └── requirements.txt または pyproject.toml
├── docs/
│   └── spec.md
├── data/                     # Git管理対象外：DB等
├── models/                   # Git管理対象外：モデル重み
├── references/               # Git管理対象外：音声素材等
├── logs/                     # Git管理対象外
├── .env.example
├── .gitignore
└── README.md
```

機能拡張に応じて、backend配下に `llm/`、`memory/`、`tools/`、`voice/`、`integrations/` 等を追加する。最初から空のモジュールを大量に作らず、実装フェーズに合わせて追加する。

### 7.2 モジュール責務

- `frontend`: 画面表示、ユーザー操作、API呼び出し
- `backend/app/api`: HTTP APIのルーティングと入出力
- `backend/app/core`: 会話制御、エージェントループ、計画、権限判定
- `backend/app/database`: DB接続、初期化、永続化
- `llm`: LLMプロバイダーとの通信（追加フェーズで導入）
- `memory`: 記憶の保存・検索（追加フェーズで導入）
- `tools`: AIが呼び出せる限定された操作（追加フェーズで導入）
- `voice`: STT/TTSと音声デバイス管理（追加フェーズで導入）
- `integrations`: 外部サービス連携（追加フェーズで導入）
- `tests`: 単体・統合テスト

### 7.3 基本処理フロー

```text
Browser UI
   |
   v
Frontend API Client
   |
   v
FastAPI Backend
   |
   +--> Authentication / Request Validation（必要な公開形態に応じて）
   |
   +--> Orchestrator
   |       |
   |       +--> Relevant Memory Retrieval
   |       +--> LLM Reasoning
   |       +--> Tool Request
   |               |
   |               v
   |           Permission Check
   |               |
   |               v
   |           Tool Execution
   |               |
   |               v
   |           Result Validation
   |
   +--> Database
   |
   v
Response to Frontend
```

LLMが出力した文章をそのままコマンドとして実行してはならない。ツール名、引数、権限を検証し、登録済み関数だけを実行する。

音声応答を要求された場合は、バックエンドが応答テキストをTTSアダプターへ渡し、Style-Bert-VITS2ワーカーの生成結果を検証してからフロントエンドへ返す。音声生成に失敗しても、テキスト応答は成功として扱う。

## 13. 開発上の制約・注意事項

1. Style-Bert-VITS2の内部実装にアプリ全体を依存させず、TTSアダプターと独立ワーカーに閉じ込める。
2. Style-Bert-VITS2のバージョンを固定し、推論API、引数、モデル形式、起動方法をそのバージョンで検証してから実装する。
3. 音声モデル、設定ファイル、BERT関連データ、参照音声、学習データはGitへ登録しない。
4. 音声の本人同意と、モデル・音声データを第三者へ再配布する許可は別に扱う。
5. LLMの出力は不確実なため、日時・数値・操作結果はアプリ側で検証する。
6. 外部から取得した文章やファイル内の指示を、システム権限として扱わない。
7. 自律処理には実行回数・時間・APIコストの上限を設ける。
8. エージェントが自身の権限、システムプロンプト、セキュリティ設定を書き換えられないようにする。
9. フロントエンドからDBへ直接アクセスさせず、バックエンドAPIで検証・制御する。
10. 外部ネットワークへ公開する場合は、認証・認可・通信保護・CORS等を別途設計する。
11. Style-Bert-VITS2の依存環境をNORN本体から分離し、既存の音声環境や他プロジェクトの環境を変更・共有しない。
12. 実装していない機能をダミー表示で完成扱いにしない。

## 14. MVPの完成定義

段階的にMVPを定義する。

### Prototype 0.1（Phase 0）

- ローカル環境でWebアプリを起動できる。
- フロントエンドとバックエンドが通信できる。
- SQLiteが初期化される。
- 設定・ログが管理される。

- Web UIから音声を主な手段としてAIと会話でき、必要に応じてテキスト入力へ切り替えられる。
- 会話履歴を保存できる。
- タスクを登録・完了できる。
- 目標とプロジェクトを登録できる。
- 今日の予定とタスクを確認できる。
- AIが日次の計画案を作れる。
- 個人データ・APIキーを公開リポジトリから除外できる。

NORN MVPでは音声入力による会話を必須とし、音声を利用できない場合のテキスト入力も提供する。Style-Bert-VITS2による音声応答、自律的な定期実行、ウェイクワード、デスクトップ常駐はMVPの必須条件とせず、後続フェーズに追加する。

## 15. 実装AI・開発者への指示

この仕様書を基準に実装すること。

- 各フェーズの開始時に、実装対象・変更ファイル・依存関係を提示する。

- Style-Bert-VITS2を初期TTSとして扱い、専用の依存環境と独立ワーカーを通じてTTSアダプターから接続する。
- 各フェーズ完了時に、起動方法、設定方法、テスト方法をREADMEまたはdocsへ記録する。
