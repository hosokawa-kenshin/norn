# NORN

音声入力を主な操作手段とするローカルWebアプリです。音声はローカルのfaster-whisperで文字起こしし、送信前に認識結果を確認できます。新しいGeminiの返答は、ローカルのStyle-Bert-VITS2で音声生成して自動再生します。

## 必要環境

- Python 3.12推奨（3.10以上）
- Node.js 22以上
- WSL上で開発する場合は、WSLディストリビューション内のLinux版Node.jsを使用してください。Windows側のnpmはWSLのUNC作業パスを正しく扱えません。
- OpenAI互換のLLM接続先。ローカルのOllamaも設定できます

## 起動

NORN直下でバックエンド環境を作成します。

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r backend/requirements.txt
cp .env.example .env
```

フロントエンドの依存関係も初回だけインストールします。

```bash
cd frontend
npm install
cd ..
```

`.env`に`LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`を設定します。APIキー不要のローカルLLMでは`LLM_API_KEY`を空にします。Ollamaの例:

```dotenv
LLM_BASE_URL=http://127.0.0.1:11434/v1
LLM_API_KEY=
LLM_MODEL=qwen2.5:7b
```

タスクの時間割当は既定で平日09:00〜18:00を使います。`.env`の`NORN_PLANNING_DAY_START`、`NORN_PLANNING_DAY_END`、`NORN_PLANNING_WORKDAYS`で変更できます。曜日は月曜を`0`、日曜を`6`としてカンマ区切りで指定します。見積時間のあるタスクはGeminiが期限まで（期限がなければ次の5営業日以内）の空き枠を検索して自動で割り当てます。予定・他タスクと重なる枠や営業時間外は登録されません。

## 会話からのタスク登録

「今日は楽器を練習しなきゃ」のような、本人の具体的な未完了作業への必要性・実行意思からもタスクを自動登録します。「登録して」と言う必要はありません。後で曲名や対象が分かった場合は同じタスクを更新し、言い直しで重複しないよう既存の未完了タスクと照合します。

時間未定なら先にタスクを保存し、「何分くらい？希望の開始日時はある？」と会話で尋ねます。「30分、明日の14時から」のように答えると同じタスクへ時間枠を保存します。希望日時がなければ最も早い空き枠を使い、重複・作業時間外等の場合は勝手に別日時へ変えず相談します。時間を後で決めたい場合は、そのように返答できます。この変更は会話での登録が対象で、追加画面の操作は変わりません。

日付だけが明示された期限はJSTのその日23:59:59とし、開始時刻や所要時間は勝手に設定しません。否定、仮定、単なる質問、他人の作業、完了済み、登録拒否、願望だけの雑談は対象外です。判定には追加のGeminiリクエストを1回使い、直近8件の会話と未完了タスクを送信します。過去の会話全体から遡って登録する処理ではありません。意味の判定は誤る可能性があるため、誤登録はタスク画面で編集・削除できます。

## Google Calendar

Google Cloud ConsoleでCalendar APIを有効にし、OAuth同意画面とテストユーザーを設定して、Desktop app型OAuth clientを作成します。`.env`の`GOOGLE_CLIENT_ID`と`GOOGLE_CLIENT_SECRET`へ値を設定してください。`start.sh`が実際に起動したAPI portに合わせてloopback callback URIを設定するため、portを手動で合わせる必要はありません。GoogleのDesktop OAuth clientはloopback redirectのportを固定登録しません。

起動後、「設定」からGoogle Calendarへ接続し、一覧から書き込み可能な同期先カレンダーを選びます。primary calendarが既定で、選択直後にそのカレンダーを同期します。その後は5分ごとの差分同期です。カレンダー選択にはGoogle Calendar events編集とcalendar list読み取りのscopeが必要です。既に接続済みのtokenにcalendar list権限がない場合は「Googleの権限を更新 / 再接続」から再度同意してください。同期先を切り替えても以前同期した予定はNORNに残り、そのカレンダーを再選択すると同期を再開します。

予定画面から終日予定・毎日/毎週/月次の繰り返しを編集できます。Google側のRRULE、元timezone、例外回、取消、終日の排他的終了日も保持します。NORNとGoogleの双方で同じ予定が変更された場合、全自動同期を停止して両側の内容を表示するので、採用する側を選んで再開してください。Google OAuth tokenはGit管理外の`data/`に保存されます。

「目標」画面では長期目標とプロジェクトを登録・編集できます。新規の進行中プロジェクトを作るとGeminiが既存タスクを確認し、重複しない初期タスクを3〜5件登録します。指定されていない期限・見積時間・優先度は設定しません。プロジェクトは目標へ任意に紐付けられ、タスク編集時にもプロジェクトを選べます。進捗率は完了タスク数から算出します。会話からも目標・プロジェクトを検索・追加・更新・削除できます。active目標は7日ごと、次のチャット入力時に関連プロジェクト/期限/タスクを根拠にレビューし、次の一歩を提案します。時間になっただけでは動かず、バックグラウンド実行や目標・タスクの自動変更はしません。

`.env`の接続先とAPIキーを設定したら、NORN直下で両方のサーバーを起動します。

```bash
bash start.sh
```

スクリプトが表示するfrontend URLを開き、マイクの使用を許可してください。8000番・5173番ポートが使用中の場合は、それぞれ次の空きポートを選びます。初回の文字起こし時にfaster-whisperの`small`モデル（約500MB）がダウンロードされます。CPU推論が既定です。対応するCUDA環境がある場合は`.env`で`STT_DEVICE=cuda`と`STT_COMPUTE_TYPE=float16`を指定できます。

## Windows常駐版

WSLのPython/CUDA環境はそのまま使い、Windows側のElectronウィンドウとトレイから操作できます。ブラウザーのタブやVite開発サーバーを起動し続ける必要はありません。初回の配置はWindowsのPowerShellで、WSL内のNORNを指定して行います。

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File "\\wsl.localhost\Ubuntu-22.04\home\fukawa\voice_project\norn\desktop\install.ps1"
```

実行ポリシー指定はこの子プロセスだけで、OS/ユーザー全体の設定は変更しません。署名を要求する環境では、内容を確認して実行を許可してください。WSLの場所が異なる場合は`-Distribution`と`-LinuxProjectRoot`で指定できます。更新時はトレイから終了してから再実行してください。

公式Electronをハッシュ確認付きで`%LOCALAPPDATA%\NORN`へ配置し、スタートメニューに`NORN`を作ります。以後はそこから起動できます。今回の設定ではログイン時自動起動がオンです。トレイの「ログイン時に起動」で変更できます。ログイン時はトレイだけで起動し、音声プロフィール登録済み・検出モデル利用可能ならハンズフリー待機を自動開始します。マイク権限の許可が必要です。

×で閉じるとトレイへ隠れ、有効化済みのハンズフリーは継続します。完全終了はトレイの「終了」を使います。「マイクを停止」は待機自体を停止し、スリープ/復帰時にもマイクを止めます。PCのスリープ中の呼び出しには対応しません。

Windows設定とログは`%APPDATA%\NORN`、会話DB・キャリブレーション・APIキー・モデルは元のWSL側へ保存します。終了時はこのアプリが起動したWSLバックエンドだけを正常終了します。既存のWeb版を併用するとGPUワーカーが重複するため、通常はどちらか一方を使ってください。

`desktop/install.ps1 -SmokeTest`は自動起動を変更せず隔離DBで検証します。API/WebSocket、×での非破棄、二重起動防止を確認し、日本語のWindows合成音声が利用可能なら仮想マイクで非表示ウィンドウのウェイク処理も確認します。実マイクでの精度やログインし直した後の動作は別途確認が必要です。

## キャラクター設定

`characters/active.json`を配置すると、Geminiの会話の名前・口調・性格などを切り替えられます。`characters/`全体はGit管理外です。設定は各会話リクエストで読み直すため、内容の編集後にサーバーを再起動する必要はありません。ファイルがない場合は従来のNORNとして応答します。壊れたJSON・空の設定・32KiBを超える設定はエラーとなります。

形式は任意の項目名と文字列値を持つUTF-8のJSONオブジェクトです。具体的なキャラクターの情報はソースコードや仕様書に記載しないでください。別の配置先は`.env`の`NORN_CHARACTER_PATH`で指定できます。相対パスはNORN直下が基準です。別の配置先もGitから除外するか、リポジトリ外を指定してください。環境変数の変更だけは再起動が必要です。

設定はGeminiへの会話指示として送信されます。Git除外は外部LLMへ送信しないという意味ではありません。予定・タスク管理機能と操作結果の事実確認は維持し、キャラクター上の架空の関係・出来事は現実の長期記憶や予定として保存しないよう指示します。既存履歴が口調へ影響することがあるため、切り替え直後は新しい会話から始めてください。

## ハンズフリー会話

初回は`.venv/bin/python backend/setup_voice_models.py`で日本語検出モデルを配置します。追加依存は`backend/requirements.txt`から導入してください。`npm install`または起動時に、VADモデルとWASMをローカル配信領域へ配置します。モデル類はGit管理外です。

ハンズフリーの初期値はオンです。音声プロフィール登録済み・検出モデル利用可能なら起動・再読み込み時に待機を開始します。マイクを許可し、**「ねぇノルン」**と呼びかけます。「ノルン」だけでは起動しません。権限拒否などで開始できなかった場合は、画面の「ハンズフリー」から再試行できます。手動で停止した後は、その起動中に自動でオンへ戻しません。待機中は日本語モデルの限定語彙検出だけをPC内で実行し、通常の文字起こしAPIやGeminiへ送信しません。会話開始後は約1.2秒の無音で発話を自動送信し、60秒無言または「待機して」「またね」等で待機へ戻ります。処理・再生中は60秒に数えません。マイク停止ボタンで待機自体も終了します。

Voskの日本語音響モデルを使う限定語彙検出であり、待機中に一般の文章を転記する用途ではありません。日本語合成音声と本人の調整用録音で検証しましたが、未知の言い方・日常の雑音環境での精度は保証していません。ブラウザー終了中やPCスリープからの起動はできません。モデル配布元は[公式Voskモデル一覧](https://alphacephei.com/vosk/models)で、日本語軽量モデルはApache 2.0です。

有効な音響プロフィールがない初回起動だけ、「初回音声セットアップ」を表示します。同意して録音開始を押し、「ねぇノルン」を4回、1秒程度ずつあけて録音し、確認後に登録します。セットアップ録音は同意・開始操作まで行いません。登録に成功したらハンズフリー待機を開始します。「後で」なら開始しません。登録後は`data/wake-profile.npz`を使い、再起動・再読み込みでも案内をスキップします。同じ呼びかけの登録済みプロフィールは再録音や上書きをしません。ウェイクワードを変更する場合は旧プロフィールを削除し、新しい呼びかけで登録し直してください。これは声による本人認証ではありません。

初回登録の音声はPC内だけで処理し、登録の成功/失敗にかかわらず一時原音を削除します。特徴量だけがGit管理外に保存されます。登録後にハンズフリーを有効化すると新しいプロフィールを使うため、API再起動は不要です。登録失敗時はやり直せます。「後で」は今回は閉じる操作で、未登録なら次回に再案内します。マイクを許可しなくてもテキスト入力は使えます。

個別の取りこぼしを手動調査するための`.venv/bin/python backend/wake_calibration.py`も残しています。この別ツールの録音はGit管理外の`data/wake-calibration/`へ保存し、外部送信しません。通常の初回登録ではこのツールを別途起動する必要はありません。

今回の本人録音4発話では検出が2回から4回へ改善しました。ただし登録に使った音声での評価を含み、未知の言い方や雑音に対する精度を保証するものではありません。「乗る」「乗るんだ」を誤起動する既知のケースも残っています。単純なしきい値の引き下げや、似た別単語の起動語追加は行っていません。

## 応答音声

音声合成は任意機能で、初期状態では無効です。特定のモデル名や兄弟ディレクトリは探索しません。テキスト会話は音声モデルなしでも利用できます。モデルの重み・日本語BERTはリポジトリに同梱していないため、利用・再配布条件を確認して別途入手してください。

1. Style-Bert-VITS2を任意の場所へ配置し、エンジン側の手順に従って専用Python環境・PyTorch等の依存関係・日本語BERTとトークナイザーを準備します。NORN本体の環境へPyTorchを追加する必要はありません。
2. 互換性のある日本語モデルの`.safetensors`または`.pth`と、そのモデルに対応する`config.json`、`style_vectors.npy`を配置します。ONNXモデルはこのワーカーでは利用できません。
3. Git管理外の`.env`に以下を設定し、NORNを再起動します。パスはバックエンドを動かすOSから見えるものを指定してください。WSLバックエンドならLinuxパスです。

```dotenv
NORN_TTS_ENABLED=1
NORN_TTS_ROOT=/path/to/Style-Bert-VITS2
NORN_TTS_MODEL=/path/to/voice/model.safetensors
NORN_TTS_DEVICE=auto
```

すべての設定パスは絶対パス、またはNORNリポジトリ直下を基準とする相対パスを使えます。Pythonはエンジン直下の`.venv/bin/python`（Windowsは`.venv/Scripts/python.exe`）を既定とし、別環境は`NORN_TTS_PYTHON`で指定します。モデルと別の場所の設定・スタイルは`NORN_TTS_CONFIG`、`NORN_TTS_STYLE_VECTORS`で指定できます。日本語BERTはエンジンの標準配置を使い、別配置ならトークナイザーを含むディレクトリを`NORN_TTS_BERT_MODEL`で指定します。`NORN_TTS_SPEAKER_ID`と`NORN_TTS_STYLE`はモデル内に存在する話者・スタイルを指定してください（既定は`0`、`Neutral`）。全項目は`.env.example`を参照してください。

`auto`はCUDAを利用可能ならGPU、それ以外はCPUを選びます。`cpu`、`cuda`、`cuda:0`等の固定指定も可能です。明示CUDAが利用できない場合はエラーとなり、テキスト会話は継続します。Windows/macOSのネイティブ音声環境は未実機検証です。現在のWindowsトレイ版のバックエンド起動は引き続きWSL方式です。

BERTはオフラインで読み込み、起動時にウォームアップして以後は常駐します。必要なデータがなければ自動ダウンロードせず失敗状態になります。旧形式のBERT重みには`data/tts-bert-cache/`へSafetensorsキャッシュを作成します。元重みは変更せず、元ファイルのパス・サイズ・更新日時が変わればキャッシュを作り直します。準備中もチャットは利用でき、返答の音声は準備完了まで待ちます。過去の履歴を開き直しても自動再生しません。「応答を読み上げる」で無効化でき、再生・停止ボタンも利用できます。ブラウザーが自動再生を拒否した場合は再生ボタンを押してください。音声失敗時もテキスト表示は継続します。生成音声はDBやファイルに保存しません。

`NORN_TTS_ENABLED=0`または指定なしならワーカーを起動しません。有効でも必須のルート・モデルが未設定なら`unconfigured`、必要ファイルの不足は`unavailable`、起動失敗は`failed`としてチャットを継続します。状態は`/api/speech/status`、起動・推論の診断ログはGit除外の`data/tts-worker.log`で確認できます。各NORN APIプロセスが専用ワーカーを持つため、通常は一つだけ起動してください。

## データとプライバシー

- 録音データは文字起こしの一時処理後に削除し、保存しません。
- 会話履歴は`data/norn.sqlite3`に保存します。
- 長期記憶は会話履歴と分けてSQLiteに保存します。新しいチャット入力があり、前回の抽出から1時間以上経っている場合に、全会話共通で未処理分から最大3件を抽出します。時間になっただけでは動かず、バックグラウンド実行もしません。質問・確認文や「前に話した？」という想起依頼は、事実として自動保存しません。「覚えて」と明示された内容はすぐ保存でき、訂正や忘却も会話から依頼できます。抽出には別のLLMリクエストを使います。
- 記憶の言い換え検索にはローカルの多言語埋め込みモデルを使います。初回の利用時にモデル（約250MB）を取得しますが、質問文・記憶文のベクトル化と検索はローカルで行い、埋め込みサービスへ送信しません。初期しきい値はcosine類似度`0.72`です。これは候補検索用の基準で、返却候補はGeminiが質問の人物・行動・場所・時期・対象と照合してから回答します。モデルが利用できない場合は語句検索へフォールバックします。パスワード、APIキー、決済情報は保存層で拒否し、正確な住所など慎重な情報は抽出対象から除外する方針です。
- 音声認識はローカルで実行します。会話テキストは設定したLLM接続先へ送信され、記憶候補の抽出にも別のLLMリクエストを使用します。
- APIキー、DB、モデルファイルはGit管理対象外です。
- 開発サーバーとAPIはループバックアドレスにのみバインドします。
